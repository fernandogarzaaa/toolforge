# Data card: toolforge function-calling SFT set

Generated by `toolforge data`. Numbers below are from the run that produced the committed
`data/processed/stats.json`; re-running with the same config reproduces them.

## Sources

- **Training**: [glaiveai/glaive-function-calling-v2](https://huggingface.co/datasets/glaiveai/glaive-function-calling-v2) (Apache-2.0), revision `e7f4b6456019f5d8bcb991ef0dd67d8ff23221ac`. 112,960 raw conversations.
- **Evaluation**: a held-out glaive split plus [BFCL v4](https://github.com/ShishirPatil/gorilla/tree/main/berkeley-function-call-leaderboard) (Apache-2.0) categories simple, multiple, parallel, irrelevance, gorilla commit `6ea57973c7a6097fd7c5915698c54c17c5b1b6c8`.

## Processing

1. **Parse** each conversation into a *decision example*: tools + first user turn -> first assistant decision (a tool call, or a text reply). Filler like "Sure, let me check" directly followed by a call is collapsed into the call.
   Parse errors: 22; conversations without a usable decision: 34,598.
2. **Schema validation**: every tool must be a valid object schema (name, typed properties, declared required params); every gold call must name an available tool, pass required/unknown-argument checks, and match declared types and enums. Rendered length capped at 2,600 characters.
   Kept 77,834; dropped: {"duplicate tool names": 351, "parameters.type must be": 119, "missing required argument": 25, "invalid tool name:": 3, "required is not a list": 3, "property": 3, "unexpected argument": 1, "too long": 1}.
3. **Dedup** on normalised user text + tool-name set: 55,624 removed.
   Categories after dedup: {"clarify": 4654, "irrelevance": 1882, "multiple": 7718, "simple": 7956}.
4. **Held-out glaive eval split** taken before training sampling: {"simple": 50, "multiple": 50, "irrelevance": 50}.
5. **Decontamination** against the glaive eval split and *all* questions of the used BFCL categories: exact normalised match or any shared 8-word n-gram. Removed 9,484.
6. **Stratified subsample** for CPU training: {"multiple": 500, "irrelevance": 199, "simple": 500, "clarify": 150} (total 1,349); 400 further disjoint prompts reserved for DPO pair mining.

## Categories

- `simple`: one tool available, one call expected.
- `multiple`: several tools available, exactly one call expected.
- `irrelevance`: tools available but none fits; the right answer is a text reply and no call.
- `clarify` (train only): the assistant asks for missing information before calling.

## Known issues and limitations

- glaive v2 is synthetic (generated by an LLM); tools are simple and repetitive (many `calculate_*`, `get_*`), so the held-out glaive split is in-distribution. BFCL is the out-of-distribution check.
- glaive has no parallel calls, so `parallel` is only evaluated (BFCL), never trained.
- Gold arguments are a single acceptable value on the glaive split (BFCL provides several); this makes the glaive split stricter than BFCL for free-text arguments.
- Text replies in glaive are not scored for content, only for the absence of a call.
